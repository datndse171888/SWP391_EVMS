I. EXECUTIVE SUMMARY
================================================================================

The Electric Vehicle Maintenance System (EVMS) is a comprehensive web-based 
platform designed to manage maintenance services for electric vehicles. The 
system enables customers to book appointments, technicians to manage work 
schedules, and administrators to oversee operations.

Key Features:
- User authentication and role-based access control
- Appointment booking and management
- Service and service package management
- Parts inventory management
- Technician scheduling and certification tracking
- Real-time slot availability checking
- Checklist management for service tasks
- Vehicle condition reporting
- Communication system (conversations and messages)

Technology Stack:
- Backend: Node.js, Express.js, TypeScript, MongoDB
- Frontend: React, Vite, TypeScript, Tailwind CSS
- Database: MongoDB with Mongoose ODM
- Authentication: JWT (JSON Web Tokens)

II. SYSTEM OVERVIEW
================================================================================

2.1 System Purpose
The EVMS system provides a complete solution for managing electric vehicle 
maintenance operations, from customer booking to service completion and 
reporting.

2.2 User Roles
1. ADMIN: Full system access, user management, system configuration
2. STAFF: Appointment management, customer support, technician assignment
3. TECHNICIAN: Service execution, task management, work scheduling
4. CUSTOMER: Appointment booking, service browsing, vehicle management

2.3 Core Modules
- Authentication Module: User login, registration, JWT token management
- Appointment Module: Booking, scheduling, status tracking
- Service Module: Service catalog, pricing, duration management
- Parts Module: Inventory management, part tracking, warranty management
- Technician Module: Staff profiles, certifications, scheduling
- SlotTime Module: Time slot management, availability checking
- Checklist Module: Task management during service execution
- Vehicle Module: Customer vehicle registration and tracking
- Communication Module: Conversations and messaging system

VI. AUTHENTICATION & AUTHORIZATION
================================================================================

6.1 Authentication Flow

1. User Registration
   - User submits: userName, email, password, fullName, phoneNumber
   - System hashes password using bcrypt
   - User record created in database
   - Verification email sent (optional)

2. User Login
   - User submits: email, password
   - System verifies credentials
   - JWT token generated with user ID and role
   - Token returned to client
   - Client stores token in localStorage/sessionStorage

3. Token Verification
   - Client includes token in Authorization header: "Bearer <token>"
   - Server verifies token signature and expiration
   - User ID and role extracted from token
   - Request proceeds if valid, rejected if invalid

6.2 Authorization Levels

ADMIN
- Full system access
- User management (create, update, disable)
- Service and package management
- Part inventory management
- Technician management
- System configuration
- Report generation

STAFF
- Appointment management
- Customer support
- Technician assignment
- Service scheduling
- Report viewing
- Cannot modify system settings

TECHNICIAN
- View assigned appointments
- Update appointment status
- Create and manage checklists
- View vehicle condition reports
- Cannot access admin functions

CUSTOMER
- Book appointments
- View services and packages
- View parts catalog
- Manage own vehicles
- View own appointments
- Cannot access staff/admin functions

6.3 Middleware Implementation

authMiddleware:
- Extracts JWT token from Authorization header
- Verifies token signature and expiration
- Attaches user info to request object
- Returns 401 if token invalid/missing

roleMiddleware:
- Checks user role against required roles
- Returns 403 if user lacks permission
- Used on protected routes

VII. BUSINESS FLOWS & WORKFLOWS
================================================================================

7.1 Appointment Booking Flow

1. Customer selects vehicle category and date
2. System queries available slots for that date
3. System checks technician availability
4. System displays available time slots
5. Customer selects time slot
6. Customer selects service or service package
7. System creates appointment with status 'pending'
8. Confirmation email sent to customer
9. Staff notified of new appointment
10. Staff assigns technicians
11. Appointment status changes to 'confirmed'

7.2 Service Execution Flow

1. Technician views assigned appointments
2. Technician starts appointment (status → 'in_progress')
3. Technician creates checklist tasks
4. Technician marks tasks as completed
5. Technician records vehicle condition (before/after)
6. Technician logs parts used
7. Technician completes appointment (status → 'completed')
8. System generates service report
9. Customer receives completion notification

7.3 Slot Management Flow

1. Admin creates time slots for technicians
2. Slots marked as 'available'
3. When appointment booked, slot marked as 'booked'
4. When appointment completed, slot marked as 'completed'
5. Admin can cancel slots (status → 'cancelled')
6. System prevents double-booking

7.4 Parts Management Flow

1. Admin adds parts to catalog
2. Admin sets part price and warranty
3. Inventory tracks part quantities
4. During service, technician logs parts used
5. System creates PartUsage record
6. Inventory quantity decremented
7. Admin monitors low stock levels
8. Admin reorders parts as needed

IX. SECURITY DESIGN
================================================================================

9.1 Authentication Security

Password Security:
- Passwords hashed using bcrypt (salt rounds: 10)
- Never stored in plain text
- Minimum password requirements enforced
- Password reset via email verification

JWT Token Security:
- Tokens signed with secret key
- Token expiration: 24 hours (configurable)
- Refresh token mechanism (future enhancement)
- Token stored securely on client

9.2 Authorization Security

Role-Based Access Control (RBAC):
- Each endpoint validates user role
- Permissions checked before data access
- Unauthorized access returns 403 Forbidden
- Audit logging of access attempts

Data Validation:
- Input validation on all endpoints
- Type checking with TypeScript
- Mongoose schema validation
- Sanitization of user inputs

9.3 Data Protection

Database Security:
- MongoDB connection with authentication
- Encrypted connections (SSL/TLS)
- Regular backups
- Data encryption at rest (future enhancement)

API Security:
- HTTPS/TLS for all communications
- CORS configuration
- Rate limiting (future enhancement)
- Request validation and sanitization

9.4 Audit & Logging

Logging:
- Authentication attempts logged
- API access logged
- Error logging
- Sensitive operations logged

================================================================================

10.1 Constraints

Technical Constraints:
- MongoDB database required
- Node.js 14+ required
- React 18+ required
- Modern browser support (ES6+)
- Internet connection required

Business Constraints:
- Appointment booking limited to future dates
- Minimum 1 hour advance booking
- Technician availability based on SlotTime records
- Service duration fixed per service type
- Parts inventory must be tracked manually

Performance Constraints:
- API response time < 2 seconds
- Database queries optimized with indexes
- Frontend bundle size < 500KB
- Maximum 1000 concurrent users

10.2 Assumptions

System Assumptions:
- Users have valid email addresses
